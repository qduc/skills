# Skills

These are agent skills: procedures an agent can follow for a particular kind of work.

There is no installer. A skill is a directory under `skills/<name>/` with a `SKILL.md` file. Read that file. The `name` and `description` in the frontmatter say when the skill applies. The rest of the file is the procedure. A skill may also keep notes, scripts, or other files next to `SKILL.md`. Use those only when the procedure tells you to.

## Optional personal profiles

[Personal coordinator profiles and new-host setup](profiles/README.md) are explicit
opt-ins, separate from the reusable skills. They do not configure a host or log in
to providers just by being present.

## Setup

The skills in this repository do not need to be installed. Optional outside engineering skills can be downloaded with Git. Run this from the repository root (or invoke the script by its full path from another directory):

```sh
./scripts/setup-protocols.sh
```

That downloads two public collections into `.external/`, which git ignores. They are not part of the skills published here:

- [mattpocock/skills](https://github.com/mattpocock/skills) lands in `.external/mattpocock-skills/skills`
- [cursor/plugins](https://github.com/cursor/plugins) (`pstack/skills`) lands in `.external/cursor-plugins/pstack/skills`

The script records both directories in `.external/catalog.env`. Load them into the shell that launches `/delegate`:

```sh
. ./.external/catalog.env
```

The file exports `COORDINATOR_PROTOCOL_CATALOG`, with the pstack catalog first. Paths containing spaces and shell metacharacters are quoted safely. Repository paths containing a colon or newline are rejected because the catalog uses `:` to separate paths.

Run the setup script again to fetch updates and fast-forward clean checkouts. Before changing either working tree, it checks both destinations and refuses unrelated existing directories, symlinks, a changed origin, detached or non-tracking branches, tracked edits, staged edits, untracked or ignored files, local commits that cannot fast-forward, and rewritten upstream history. It preserves those files and commits; move or preserve your work before retrying. It also refuses unrelated or edited `catalog.env` content rather than overwriting it. The exact catalog generated by the previous script version is upgraded automatically. Fetches can update Git metadata before a refusal, and a later Git/download error can leave a partially completed setup; rerun after resolving the error.

To use different sources, set `MATT_SKILLS_URL` and `CURSOR_PLUGINS_URL` to Git repository URLs or local repository paths before running setup. Relative local paths are resolved from the directory where you run setup; quote values containing spaces. Existing clones must still match the selected sources. The plugins source must contain `pstack/skills`, and the mattpocock source must contain `skills`.

If you skip setup, `/delegate` uses its normal fallback without external skills. To stop using downloaded catalogs in a shell that loaded them, run `unset COORDINATOR_PROTOCOL_CATALOG` before removing `.external/`.

The setup integration tests create real local Git repositories, run the actual script, source the catalog with POSIX `sh`, and invoke the existing Coordinator resolver. They block Git network protocols and do not change global Git configuration:

```sh
python3 -m unittest discover -s scripts -p 'test*.py'
```

## Skills

- **[review](skills/review/SKILL.md)** — Routes artifact, code, module, invariant, complexity, and repository reviews, and finding triage.
- **[engineering](skills/engineering/SKILL.md)** — Routes investigation, debugging, implementation, testing, profiling, and bug retrospectives.
- **[browser](skills/browser/SKILL.md)** — Routes browser QA and Playwright CLI workflows.
- **[skill-development](skills/skill-development/SKILL.md)** — Routes skill creation and workflow evolution.
- **[agentic-loop](skills/agentic-loop/SKILL.md)** — Pursues delegated outcomes through planning, action, observation, verification, and adaptation, loading methodology only when needed.
- **coordinator-setup** — Discovers host capabilities and configures optional coordinator adapters in an external host profile without rewriting the base skill.
- **delegate** — User-invoked (`/delegate`). Splits substantial work across headless or native workers through a code-driven runtime that owns the flow and gates, and delivers Git changes or report/file artifacts. The agent answers typed judgments and performs requested native host calls.
- **[duc-mode](skills/duc-mode/SKILL.md)** — Duc's working style for any code change, directly or as a worker: evidence, real-app verification, decisions, and when to ask.
- **herdr** — Inspects and coordinates Herdr workspaces, tabs, panes, terminals, and agents from the command line without disrupting work already running.
- **model-benchmark** — Measures coding models and agent harnesses on real engineering tasks from the term2 repository, including solve rates and blind grading of candidate diffs.
- **[research](skills/research/SKILL.md)** — Sources, compares, and synthesizes evidence into traceable answers to bounded questions.
- **risk-first-build** — Starts non-trivial builds with concrete discovery, verifies assumptions in order of risk, and reports evidence honestly.
- **simplicity-architect** — Proposes software designs built on strong invariants and a small complexity budget, keeping edge cases from growing into extra defensive machinery.
- **supervise-panes** — Runs and supervises hand-watched workers, such as agents in Herdr panes, through a phased procedure with a durable task record; also resumes older manual coordinator tasks. Uses the delegate skill's scripts.
- **term2** — Starts, configures, and runs term2 for interactive coding sessions or one-shot command-line tasks.

## Agentic Loop primitives

Use `agentic-loop` to own a delegated outcome. At the point of need, load
`engineering`, `review`, `browser`, or `research`, then read only the relevant
workflow. Use `skill-development` when a real methodology gap remains. The
former skill names identify workflows inside these parent skills.
